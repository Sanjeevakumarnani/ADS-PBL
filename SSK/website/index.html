The Algorithms

Six Sorting Techniques

Each algorithm uses comparisons to order elements. See how they differ.

🫧

Bubble Sort

Repeatedly compares adjacent elements and swaps them if out of order. Simple but slow.

O(n²) Worst O(n) Best Stable In-place
for i in 0..n:
  for j in 0..n-i-1:
    if a[j] > a[j+1]: swap
🎯

Selection Sort

Selects the minimum from the unsorted part and places it at the front each pass.

O(n²) Always Min Swaps In-place
for i in 0..n:
  min = find_min(i..n)
  swap(a[i], a[min])
📌

Insertion Sort

Inserts each element into its correct position in the already-sorted left portion.

O(n²) Worst O(n) Best Stable Adaptive
for i in 1..n:
  key = a[i]
  shift right while a[j]>key
🔀

Merge Sort

Divides array in half recursively, then merges sorted halves back together.

O(n log n) Always Stable O(n) Space
merge_sort(a, l, r):
  mid = (l+r)/2
  merge(left, right)
⚡

Quick Sort

Partitions around a pivot. Fastest in practice with median-of-three pivot selection.

O(n log n) Avg O(n²) Worst In-place
quick_sort(a, lo, hi):
  p = partition(lo,hi)
  recurse(lo,p) (p,hi)
🏔️

Heap Sort

Builds a max-heap then extracts the maximum element one at a time.

O(n log n) Always In-place O(1) Space
build_max_heap(a)
for i = n-1..1:
  swap(a[0],a[i]); heapify

Fastest Overall

Quick Sort wins in practice due to excellent cache behavior, despite O(n²) worst case.

💾

Memory Efficient

Bubble, Selection, Insertion, and Heap Sort all sort in-place with O(1) extra space.

🔒

Guaranteed O(n log n)

Merge Sort and Heap Sort guarantee O(n log n) in all cases — no bad inputs.

📐

Nearly Sorted?

Insertion Sort is unbeatable on nearly-sorted data, running close to O(n).
